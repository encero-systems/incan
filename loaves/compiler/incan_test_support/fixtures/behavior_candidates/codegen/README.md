# Behaviour-fixture candidates for the codegen retire tests

Candidates written while twinning the `incan_emit` retire tests outside the frozen emitter (the `codegen.rs` unit tests, the `checked_program` tests and the small integration test files; the inventory rows that name a file here are the `open` rows of those files). The format and the reason a candidate is not in an area are those of `loaves/compiler/incan_test_support/fixtures/behavior/README.md`; this file says what waits here and how far each candidate was verified.

Every program here imports through `rust::`, so none of it can be admitted to an area: under the compiler suite a `rust::` program needs source-current project inspection authority, which only an explicit bake of its project records, and that bake runs Rust inspection through Cargo. None of these programs was executed when written, either: the same bake is the only way to run them, and Cargo was not available where they were written. What was verified is the Rust side (`rust_demo_interop/rust/{demo,demo_derive,client_probe}` and `rust_demo_async/rust/demo_async` compile with a direct `rustc --crate-type lib` / `--crate-type proc-macro`); the Incan side was read against the language reference and the retired tests' own programs, and the expected lines were reasoned from the programs. `incan check` cannot look at them either: without inspection authority it refuses a `rust::` program before typing it, which is also why `toml_value_rusttype_qualifier_refused.incn` cannot be an `expect-diagnostic` fixture yet. Whoever admits a candidate runs it first and corrects its header from what the program actually shows.

- `rust_demo_interop/`: one project whose in-fixture `demo` crate makes real every item the retired `codegen.rs` tests described through synthetic inspection metadata over `rust::demo` (a boxed variant, an `&impl` handle, owner-specialised and named-field constructors, a tuple struct, an owned mutable command buffer, `FooBar` with projected `&mut` tuple leaves and its unprojected `PlainBar` control, two projected arguments, a `Component` marker with a `demo_derive` proc-macro, an `f32` boundary, keyword-spelled fields, a borrowing `Builder`, a `SessionContext` taking nested options, a `Message` trait, a `Mac` trait with the three receiver modes, an `Expression.eval` taking a closure) and a `client_probe` crate with the reqwest-shaped `Client`/`RequestBuilder`. Twenty-two rows point at it.
- `rust_demo_async/`: the async shapes (`consume(&State, &Plan)`, an async `register_csv(&self, &str, &str, CsvReadOptions)`, an argument returned by a Rust method) over an in-fixture `demo_async` crate. Five rows.
- `rust_std_root_module.incn`, `rust_std_imports_unused_and_aliased.incn`, `rust_option_map_closure.incn`, `rust_core_string_slice_add_assign.incn`: programs over `rust::std` and the stdlib core crate.
- `toml_edit_traversal.incn`, `toml_value_borrowed_matching.incn`, `toml_value_rusttype_qualifier_refused.incn`: programs over the `toml` and `toml_edit` crates the toolchain already depends on.
- `rust_supertraits.incn`: marker traits over Rust supertraits (`Display`, `From` under an alias, `DeserializeOwned`).
