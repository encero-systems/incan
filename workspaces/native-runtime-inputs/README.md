# Native runtime identity

This private Incan workspace projects build-unit inputs from an explicit canonical native receipt catalog, compiler identity, provider records, selected stdlib facets and portable dependency declarations. It reads no Cargo lock or manifest. Required runtime facets come from the existing toolchain registry. The transport selects their owning Loaf identities from the admitted native declarations, verifies that those owners match the exact receipt catalog, and retains the leases through projection. A Rust facet name can differ from its package name; filenames and ambient manifests do not establish that association. This workspace receives Loaf identities and does not maintain a second runtime registry.

The file exchange supports runtime projection and dependency-root projection. Both validate the catalog and bind the response to the exact request. Runtime projection additionally requires all declared runtime units. Dependency declarations retain aliases, package renames, version requirements, features, default-feature activation and optionality. Path declarations carry a source kind rather than a machine-local directory. Existing native selection must subsequently verify the corresponding admitted source, version, features and domain; an identity digest alone grants no compilation authority.

The compiler transport is removable debt for the minimized API gap tracked by [#1698](https://github.com/encero-systems/incan/issues/1698). The Incan bootstrap prepares this executable internally and binds its bytes in the source compiler's receipt before installing it beside that compiler. Compiler calls verify the compiler output/receipt binding and the engine bytes. A native projection refusal cannot authorize a Cargo fallback.

Focused tests exercise binding and refusal. They do not prove compiler integration, installed-toolchain packaging, Cargo metadata independence of every route, or Just Enough Compilation across compiler edits. Those remain separate recovery gates.

The migration also supports `incan.ordinary-native-inputs.request/1`. Its driver entry is `ordinary_runtime_inputs(closure, intent, rustc, providers, facets, dependencies)`. The closure is an original `NativeLoafClosure`, retained through the executable exchange. The driver reselects its exact roots with the existing graph verifier, checks complete physical child bindings and both original owners, and rejects unrooted records. It checks target-domain units against the consumer target and host-domain units against the actual selected rustc host. Profile, toolchain, compiler executable digest and commit must match the original recipes. This does not reacquire native Store owners. After projection it revalidates original bytes before returning the inputs.

The ordinary request carries canonical alias-to-record roots, sorted immutable selected-record identities, consumer coordinates/features, provider records, facets and portable declarations. Original record identities bind full source, features, domain, native receipt/output and physical edges. Exact compiler receipt/output and prepared engine digests bind the executable exchange. Its response uses ordinary keys such as `ordinary-native-roots` and `ordinary-native-records`; it carries no SDK inventory, catalog or revision. The legacy request and response remain compatible during caller migration. These are physical build-unit inputs, not complete semantic, macro or reserved namespace authority. Root selection still requires the caller's current declarations and lock authority.

`src/test_ordinary_runtime_inputs.incn` exercises the production Incan projection with unchanged repeats, changed roots/aliases/records/compiler/intent/provider/features/declarations, and malformed or absent authority refusals. These wire tests do not admit native owners. The separate ignored driver selector `build::native_runtime_inputs::tests::ordinary_engine_original_closure_first_repeat_and_refusals` uses the genuine native producer and actual receipt-bound executable. It requires `INCAN_ORDINARY_ENGINE_GRAPH`, `INCAN_ORDINARY_ENGINE_INDEX` and `INCAN_ORDINARY_ENGINE_BLOBS`, with a small resolved graph containing two distinct target records and one host record. It tests original owner retention, changed physical selections, intent/host/compiler refusals, and removal/restoration of original record payload and native output. Invoke it explicitly through the native runner's `--exact` selector, which includes that selected ignored test. Production caller wiring and all native execution remain separate gates; source controls alone do not establish SDK removal or performance acceptance.
