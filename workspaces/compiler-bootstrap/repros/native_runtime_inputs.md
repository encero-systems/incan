# Native runtime build-input API gap

Tracked by [#1698](https://github.com/encero-systems/incan/issues/1698), whose acceptance explicitly requires no Cargo manifest or lock outside ruled-in test data. `make test-one` with `TEST_EXACT=numeric_output_matches_legacy` on the source-built compiler fails during the library fixture bake with `failed to read Oven runtime lock /Cargo.lock`. The retained reproduction is `make-selected-numeric-unseeded-proof.json` in the recovery evidence directory.

`oven_rustc::loaf::runtime_build_unit_inputs` exposes compiler identity, provider records, stdlib facets and the dependency digest. It has no parameter for native catalog evidence and always reads eight runtime Cargo manifests plus the runtime lock. The minimized private `repros/native-runtime-api-gap` project passes `incan check` but `incan oven bake` fails with Rust E0432: no `runtime_build_unit_inputs_from_native_catalog` in `oven_rustc::loaf`. The check alone was insufficient; the bake diagnostic is retained in `execution/native-runtime-api-gap-repro-bake.log`. The normal driver invokes the mandatory reader before adding its existing native catalog receipt input, so an Incan caller cannot replace that projection through the current API.

`workspaces/native-runtime-inputs/src/runtime_inputs.incn` owns the replacement projection. It accepts explicit normalized compiler/provider/feature records, the canonical native receipt catalog, and required runtime unit names from the existing toolchain registry. It reads no ambient source metadata. Its response binds the request and catalog and keeps provider, feature, dependency and runtime unit inputs distinct.

The minimal workaround is a typed compiler transport for that Incan function: exchange caller-owned JSON files with a prepared engine beside the rebuilt compiler, validate the request/catalog binding, and return the resulting input map. The bootstrap binds and installs the engine beside the compiler. The transport must not resolve dependencies, select policy, invent runtime unit names, authorize an unbound catalog, or fall back to Cargo on a native refusal. It is removable debt until compiler build-input dispatch is authored directly in Incan. The legacy reader remains for explicit compatibility input only.
