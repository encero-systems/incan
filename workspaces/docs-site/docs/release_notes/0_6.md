# Incan 0.6 — in development

> **Development release note.** Incan 0.6 has not shipped. The dev.8 entries describe the development toolchain; they do not announce a published release archive.

## The release in one sentence

**0.6 compiles checked Incan directly to native artifacts, with Oven owning projects and ordinary Loaves supplying libraries and standard packages.**

## Why this release exists

0.5 established compiler-owned foundations, checked project boundaries, and the first Oven Alpha evidence. It still retains generated Rust in the normal backend path and leaves Cargo-shaped build behavior too close to the center of the system.

0.6 is the architectural cutover. Its purpose is not to rewrite every compiler component in Incan immediately. It is to put Incan in a position where large parts of its internals can begin moving into Incan source deliberately, while Rust stays a bounded host capability rather than a second semantic authority.

## Features and enhancements — in development

### dev.9

- **Rust interop**: `?` preserves a native `Result` success payload's shared or exclusive reference, including a receiver obtained from `guard.as_mut().ok_or("closed")?`. ([#2481](https://github.com/encero-systems/incan/issues/2481))
- **Rust interop**: Numeric arguments that violate a parameterized native trait bound are refused while checking, with the bound named. For example, `command.args(range(3))` cannot supply `int` items where `AsRef<OsStr>` is required. ([#2481](https://github.com/encero-systems/incan/issues/2481))
- **Rust interop**: A half-open range literal passed to a native generic parameter takes its unsuffixed endpoints' type from the selected trait bound. `values.drain(0..1)` therefore supplies the `usize` endpoints its `RangeBounds<usize>` bound requires. ([#2481](https://github.com/encero-systems/incan/issues/2481))
- **Rust interop**: A mutable slice method reached through a native owner's `DerefMut`, such as `values.sort_by_key(...)` on a Rust `Vec`, keeps the receiver's exclusive borrow through the dereference. A callback returning a borrowed scalar without a retained output-lifetime contract is refused while checking. ([#2481](https://github.com/encero-systems/incan/issues/2481))
- **Rust interop**: A local can take a native method's open result type from a later typed use: `total = values.into_iter().sum()` followed by a typed return fixes `sum`'s own result parameter. A method result that stays open is refused with `INCAN-T0122` naming the parameter. ([#2481](https://github.com/encero-systems/incan/issues/2481))
- **Language**: A `with` bound may name a type, which only that type satisfies, so overloads are selected by an explicit type argument (`cast[Int](expr)`), also through an alias of the overload set. Built-in types are accepted in either spelling in bounds. ([#1033](https://github.com/encero-systems/incan/issues/1033))
- **Compiler**: A decorated function whose type parameters do not appear in its signature compiles with any parameters and result type, not only as a function with no parameters that returns `str`. Each closed instance, such as `cast[Int]`, is decorated once, on its first call. ([#1033](https://github.com/encero-systems/incan/issues/1033))
- **Rust interop**: A concrete class implements a method-only Rust trait with `with Trait`: each class method named like a trait method implements it, the other trait methods keep their defaults, and Rust checks the implementation when the program is built. ([#2481](https://github.com/encero-systems/incan/issues/2481))
- **Rust interop**: A class or Rust value passes to a Rust parameter that takes a reference to a trait object, such as `&mut (dyn Callbacks + Send)`, by a borrow of the value. Each bound of the object must hold: a class holding an `Rc` is refused as `Send`. ([#2481](https://github.com/encero-systems/incan/issues/2481))
- **Rust interop**: A Rust struct field whose type a program cannot hold stays opaque instead of hiding the whole struct: the other fields stay readable and writable, and using the opaque field is refused. ([#2481](https://github.com/encero-systems/incan/issues/2481))
- **Rust interop**: A Loaf's Incan units may use rustc's internal interface when the Loaf declares it in `[build]`, for example `unstable-features = ["rustc_private"]`, `toolchain-components = ["rustc-dev"]` and `sysroot-dependencies = ["rustc_driver"]`. A program can then import `rust::rustc_driver` and run rustc's own driver. A unit whose Loaf does not declare it is refused as before, and the declaration is part of the unit's identity. ([#2481](https://github.com/encero-systems/incan/issues/2481))
- **Tooling**: A `[[rust.bin]]` declaration of `unstable_features`, `toolchain_components` or `sysroot_dependencies` is validated like the `[build]` keys, and other `[[rust.bin]]` keys are refused instead of ignored. ([#2481](https://github.com/encero-systems/incan/issues/2481))
- **Rust interop**: `incan check` refuses a Rust method call whose arguments check but whose native callee cannot be selected, with `INCAN-T0122` naming the callee and why: a type parameter nothing in the call fixes, no implementation that applies to the receiver, or several that apply equally. Such a call passed checking and then stopped the build. A Rust associated call such as `HashMap.new()` whose binding's first type-dependent use does not fix its type arguments is refused the same way; one with no type-determining use keeps `INCAN-T0105`. ([#2481](https://github.com/encero-systems/incan/issues/2481))
- **Rust interop**: A local bound to a Rust associated call that leaves its owner's type arguments open, such as `mut table = HashMap.new()`, takes them from its first type-dependent use: a method call such as `table.insert("a", 1)` or `values.push(1)`, passing it to a typed parameter, returning it from a typed function, or assigning it to an annotated place. Reads such as `len(table)` or `table.is_empty()` that need none of the open arguments leave the local available for a later fixing use. The local then has that type, as if it were annotated, and a later use that conflicts with it is refused as a type mismatch. Such programs passed checking and then stopped the build. ([#2481](https://github.com/encero-systems/incan/issues/2481))
